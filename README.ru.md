# Roistat MCP

**Разберите, что происходит между расходами на рекламу и продажами.**

> MCP-сервер для сквозной аналитики Roistat: каналы, ROI/CPL/CPO, сравнение периодов, лиды, заказы, звонки и визиты по разрешённым проектам, с маскированием персональных данных.

Сравните периоды, найдите изменения в потоке заявок и разберите заказы или звонки за показателями отчёта. Roistat MCP даёт ассистенту доступ к аналитике и связанным с CRM данным разрешённых проектов. Телефоны, email и IP посетителей в поддерживаемых ответах маскируются.

[Установка](#установка) · [Подключение к ассистенту](#подключение-к-ассистенту) · [Issues](https://github.com/zai-one/roistat-mcp/issues)

Например, попросите ассистента:

> Сравни прошлую неделю с предыдущей по моему проекту: расходы на маркетинг, заявки, продажи и выручку. Отдели подтверждённые изменения от гипотез, которые нужно проверить.

## Что можно сделать

| Задача | Возможности MCP |
|---|---|
| Разобрать результаты | Аналитические отчёты, сравнение периодов и ежедневная статистика с поддерживаемыми метриками и моделями атрибуции. |
| Изучить воронку | Заказы, статусы, заявки и отчёты по воронке разрешённых проектов. |
| Проверить события за цифрами | Коллтрекинг, визиты, клиенты и дубли заявок с маскированием поддерживаемых персональных полей. |
| Проверить настройку и расходы | Официальные индикаторы состояния проекта (синхронизация CRM, счётчик, пересчёт аналитики), рекламные каналы, введённые вручную расходы и менеджеры CRM (только чтение). |
| Поделиться проверяемым отчётом | [Пакет аналитики](docs/ANALYTICS_BUNDLE.md#русский): один или два периода, итоги провайдера, атрибуция, точные параметры запроса и JSON/CSV. Пропуски отличаются от нулей. |

## Почему этот MCP

- Ленивая загрузка инструментов (опционально): `ROISTAT_TOOL_LOADING=lazy` (или выбор в мастере настройки) — старт с небольшим ядром, наборы включаются по запросу; см. [Ленивая загрузка инструментов](#ленивая-загрузка-инструментов).
- Allowlist проектов; телефоны, email и IP посетителей маскируются в поддерживаемых ответах.
- Запись: `roistat_prepare_write` → одобрение оператора → `roistat_apply_write`; `ROISTAT_READ_ONLY=1` убирает запись.
- Аналитические пакеты с точными параметрами запроса и JSON/CSV; отсутствие данных не превращается в ноль; Markdown-таблицы для компактных ответов.
- Другие Roistat MCP на GitHub ([NatrixAi/roistat-mcp](https://github.com/NatrixAi/roistat-mcp), 16 инструментов; [theYahia/roistat-mcp](https://github.com/theYahia/roistat-mcp), 6) не маскируют персональные данные.

## Ленивая загрузка инструментов

Ленивая загрузка инструментов (опционально): `ROISTAT_TOOL_LOADING=lazy` стартует с небольшим ядром и `roistat_enable_toolsets`, остальные наборы включаются по запросу (`tools/list_changed`). Стоимость старта (tools/list + instructions, ≈символы/4): eager ≈5164 токенов, lazy ≈1435 токенов (−72%). По умолчанию `eager` — без изменений; если клиент не поддерживает `tools/list_changed`, оставьте `eager` (или перечислите наборы в `ROISTAT_TOOLSETS`): переподключение создаёт новую сессию без наборов, включённых в старой. Область: включение действует в пределах MCP-сессии (session visibility FastMCP), включённые одним клиентом наборы не видны другому. HTTP-транспорт здесь stateless (каждый запрос — отдельная сессия), поэтому включение там не сохраняется: для общего HTTP используйте `eager` или `ROISTAT_TOOLSETS`.

Клиенты и `notifications/tools/list_changed` (проверено по официальной документации, changelog или заявлениям мейнтейнеров, 2026-10):

| Клиент | `tools/list_changed` | Источник |
|---|---|---|
| Claude Code | Да (интерактивно: tools, prompts, resources; `-p`/Agent SDK: только tools) | [docs: Dynamic tool updates](https://code.claude.com/docs/en/mcp) |
| VS Code (GitHub Copilot) | Да (dynamic tool discovery); новые инструменты могут стать доступны агенту только со следующего хода | [docs](https://code.visualstudio.com/api/extension-guides/ai/mcp), [#303012](https://github.com/microsoft/vscode/issues/303012) |
| Gemini CLI | Да (обновляет реестр инструментов) | [PR #14375](https://github.com/google-gemini/gemini-cli/pull/14375), [PR #21050](https://github.com/google-gemini/gemini-cli/pull/21050) |
| Cursor | Ненадёжно: регрессия в 3.12.x подтверждена командой Cursor; используйте `eager` (перезапуск сбрасывает включённые в сессии наборы) | [forum](https://forum.cursor.com/t/mcp-server-regression-does-not-reload-tools-disconnect-does-nothing-ignores-mcp-json-changes-etc/166216) |
| Claude Desktop, Windsurf, Codex CLI, Cline, Zed, Continue | Не проверено: официальных данных нет; используйте `eager` или `ROISTAT_TOOLSETS` | — |

## Установка

Хотите установить готовый пакет? [Установка релиза и создание конфигурации клиента](INSTALL.md#install-a-release-package) работают без клонирования исходников.

Нужны **Python 3.12–3.14** и [uv](https://docs.astral.sh/uv/getting-started/installation/). Можно клонировать проект через Git или [скачать ZIP](https://github.com/zai-one/roistat-mcp/archive/refs/heads/main.zip). Для ZIP откройте распакованный каталог и пропустите первые две команды.

Нужны API-ключ Roistat и ID проектов, к которым вы хотите дать доступ. Настройщик сохраняет ключ локально и задаёт список проектов.

```sh
git clone https://github.com/zai-one/roistat-mcp.git
cd roistat-mcp
uv sync --frozen
uv run --frozen python scripts/configure.py
uv run --frozen roistat-mcp --config mcp.local.json --check-config
```

Настройщик создаёт локальную конфигурацию и сохраняет секреты в приватных файлах. Если конфигурация уже существует, он не перезапишет её. `--check-config` проверяет локальные настройки; доступ к аккаунту проверяется первым запросом ниже.

## Подключение к ассистенту

Добавьте конфигурацию в MCP-клиент, использующий раздел `mcpServers` (например, Claude Desktop или Cursor). Замените `/ABSOLUTE/PATH/` своим абсолютным путём; на Windows в JSON можно использовать `D:/Tools/`.

```json
{
  "mcpServers": {
    "roistat": {
      "command": "uv",
      "args": [
        "--directory",
        "/ABSOLUTE/PATH/roistat-mcp",
        "run",
        "--frozen",
        "roistat-mcp",
        "--config",
        "/ABSOLUTE/PATH/roistat-mcp/mcp.local.json"
      ]
    }
  }
}
```

Клиент сам запускает MCP-сервер. После обновления списка инструментов отправьте первый запрос. Для другого формата конфигурации используйте те же `command` и `args`; `uv` должен быть доступен процессу клиента.

### Первый запрос

> Покажи доступные проекты Roistat и метрики для аналитического отчёта. Уточни, какой проект использовать.

Вы увидите проекты, доступные API-ключу, и каталог поддерживаемых показателей. Для отчёта выберите проект из разрешённого на сервере списка; пустой или частичный ответ не доказывает отсутствие активности.

Если инструменты не появились, проверьте абсолютный путь, доступность `uv` и результат `--check-config`. Для ошибки доступа проверьте учётные данные и права аккаунта. [Подробная установка и диагностика](INSTALL.md).

## Управление доступом и ограничения

При сравнении периодов выбирайте одну модель атрибуции. Просмотр пользовательских метрик не делает каждую из них доступной в отчётах: инструмент использует определённый список. Для изменения данных Roistat нужны отдельная настройка и подтверждение оператора (`ROISTAT_WRITE_ENABLED`, allowlist проектов; заказы, клиенты; сценарии и номера коллтрекинга и события — только если перечислены в `ROISTAT_WRITE_OPERATIONS`). Opt-in набор `extras` (`roistat_extra_read`, включается `ROISTAT_TOOLSETS=all` или `default,extras`) читает сценарии и номера коллтрекинга, журнал событий и ленту клиента с маскированием персональных данных.

Для работы по сети предусмотрен HTTP с проверкой токенов. [Настройка HTTP](INSTALL.md#http), [конфигурация и права](docs/RUNTIME.md), [подключение Python-пакета](INSTALL.md#python-package-and-platform-integration).

## Обновления

Попросите ассистента вызвать `roistat_check_update`. Инструмент сравнивает установленную версию с
[последним релизом](https://github.com/zai-one/roistat-mcp/releases) через публичный GitHub API
(без токенов, таймаут 3 секунды, результат кэшируется на 24 часа рядом с файлом состояния) и возвращает
текущую и новую версии, ссылку на описание релиза и команду обновления
(`git pull --ff-only && uv sync --frozen` для клона, `uv tool install --force ...` для релизного пакета).
Если о новой версии уже известно из кэша, сервер один раз упоминает её в стартовых инструкциях и в
`roistat_health`. Ничего не устанавливается автоматически. Без сети проверка возвращает `status: unknown`,
а сервер продолжает работать; после сбоя повторный запрос делается не раньше чем через 30 минут.
При старте сервер в фоне обновляет этот кэш запросом к `api.github.com` (анонимно, не чаще раза в сутки),
в том числе в HTTP-развёртываниях. Отключить: `ROISTAT_DISABLE_UPDATE_CHECK=1`.
